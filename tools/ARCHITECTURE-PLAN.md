# Архитектура и план: админка, медиашкола, карты и документы

Состояние на 12 ноября 2026. Финальная сборка `2026-11-12-04`; этапы 0–4 выполнены,
разрешение на выкладку получено. Ниже — архитектура и порядок работ; исторические
пометки «сделано» относятся к своим этапам.

---

## 1. Что есть сейчас (проверено по коду, не по описанию)

### Админка

Одна страница `/admin`, внутри 9 вкладок: обзор, люди, материалы, редакции, карты,
поддержка, почта, сайт, сервер. Вкладки переключаются без перезагрузки, состояние
хранится в браузере. Всё рисует `assets/js/app.js` (6,4 тыс. строк), данные — через
`api/index.php` (3,3 тыс. строк), хранилище — JSON-файлы в `smena-data/`.

| Раздел | Что реально работает |
|---|---|
| Обзор | счётчики участников, редакций, заявок, обращений, почты, режима работ |
| Люди | список с поиском по имени/почте, карточка одним экраном: профиль, материалы, заявления, карты, переписка |
| Материалы | очередь присланного, публикация и возврат на правки с замечанием |
| Редакции | создание редакции, заявки, отделы ЖУР/SMM/КИНО, назначение руководителя |
| Карты | заявки на пресс-карту, одобрение, номер `СК-ГГГГ-NNNN`, отметка доставки |
| Поддержка | обращения с сайта, закрытие с ответом на почту |
| Почта | SMTP, отправитель, проверка письмом |
| Сайт | техработы, объявление, карточки основателей |
| Сервер | диагностика, пароль редакции, журнал действий |

**Чего нет:** бокового меню, глобального поиска, уведомлений, фильтров и сортировки
таблиц, «требует внимания», графиков, отдельной страницы участника со вкладками,
управления картами (продление, блокировка, отзыв), конструктора карт, раздела
документов, курсов.

### Участники

* Роли: исторические 5 (`Директор`, `Администрация`, `Редакционный администратор
  региона`, `Редакционный основатель`, `Пользователь`) → в этапе 1 добавлены 10 новых
  и матрица полномочий.
* Данные: имя, почта, регион, амплуа («Автор текстов» и др.), bio, аватар, согласие.
* Нет: отделов, должностей, уровней, последней активности (добавлено), блокировок
  (добавлено), внутренних заметок (добавлено), истории изменений профиля.

### Пресс-карты

* Заявка из кабинета (`card-apply`), 5 публикаций для права на заявку, доставка
  лично в Москве или почтой, решение редакции, номер, отметка об отправке.
* Бланк — PDF `assets/docs/blank-press-karty.pdf`, поля вписываются от руки.
* Нет: QR, страницы проверки подлинности, срока действия, продления, блокировки,
  отзыва, истории карт, шаблонов, генерации PDF с данными участника.

### Медиашкола

Только лендинг `/media-school` с текстом программы. Нет ни курсов, ни уроков,
ни прогресса, ни заданий, ни проверки.

### Документы

9 PDF в `assets/docs`. Хозяева файлов: `tools/build-docs.py` (пресс-кит, кодекс,
памятка, программа), `tools/build-legal.py` (политика, соглашение, бланк карты),
`tools/build-consent.py` (два согласия). Лежат статикой; из админки не редактируются,
версий и журнала выпуска нет.

### Хранилище

`smena-data/*.json` вне `public_html`: `users`, `tokens`, `posts`, `cards`,
`editorials`, `editorial-apps`, `consents`, `portfolio`, `support`, `recovery`,
`messages`, `config`, `mail`, `site`, `founders`, `admin-log`, `rate`, `login-rate`,
`activity`, `points`, `person-notes`, `backup/`.

## 2. Добавлено в этапе 0–1 (эта сборка)

1. `api/lib/permissions.php` — 15 ролей, матрица полномочий, наследование по уровню,
   персональные исключения (`perms+`/`perms-`), запрет поднимать себя и трогать равных.
2. `api/lib/points.php` — журнал баллов: каждая операция с основанием, автором и
   комментарием; баланс = сумма операций; лимит 500 за операцию; списание только
   с основанием; повтор за тот же объект не начисляется.
3. `api/lib/backup.php` — ежедневная копия JSON в `smena-data/backup/ГГГГ-ММ-ДД`,
   хранение 14 дней, запуск при первом заходе, доступ только редакции.
4. Новые маршруты: `points-rules`, `points-history`, `points-add`, `points-leaderboard`,
   `person-note`, `person-status`, `backups`, `backup-now`.
5. Карточка участника отдаёт: баллы и их историю, внутренние заметки, хронологию
   (регистрация, материалы, карты, согласия, заявки, баллы, сообщения), статус
   аккаунта, последнюю активность, полномочия.
6. Список участников отдаёт колонки для таблицы: номер, баллы, статус, карта,
   редакция, амплуа, уровень, последняя активность, согласие.
7. Все проверки `is_top_admin` в админских маршрутах переведены на полномочия —
   теперь роль «Редактор» и «Администратор» действительно что-то могут, а «Участник»
   не может ничего административного.
8. Баллы начисляются автоматически за опубликованный материал по правилу формата
   (только если материал пришёл из аккаунта: `authorId`).

Проверка: `tools/tests/api-checks.js` — 45 проверок на настоящем PHP 8.4.

## 3. Архитектура, которую предлагаю

### Сервер

Единая точка входа `api/index.php` остаётся, но разрастается по модулям в `api/lib/`:

```
api/index.php          маршрутизатор (существующие маршруты не трогаем)
api/smtp.php           почта (есть)
api/lib/permissions.php права (есть)
api/lib/points.php     баллы (есть)
api/lib/backup.php     копии (есть)
api/lib/cards.php      карты: жизненный цикл, история, продление, отзыв
api/lib/templates.php  шаблоны карт: стороны, слои, переменные, версии
api/lib/qr.php         QR-код (своя реализация, без внешних сервисов)
api/lib/pdf.php        PDF: текст, шрифт с кириллицей, картинки, QR
api/lib/docx.php       DOCX: документ Word из блоков
api/lib/school.php     курсы, уроки, задания, проверки, тесты
api/lib/docs.php       документы: шаблоны, реквизиты, версии, журнал
```

Принципы: каждое действие — маршрут с `require_cap`, каждая запись — через
`write_json` (атомарная замена), каждое изменение — в `admin-log.json`.
Новые данные — только новыми файлами; существующие форматы расширяются полями,
старые значения читаются как раньше (миграции неразрушающие).

### Данные

| Файл | Что хранит |
|---|---|
| `cards.json` (расширяется) | заявка + карта: статус `pending/issued/active/expired/blocked/revoked/rejected`, `templateId`, `templateVersion`, `validUntil`, `history[]`, `qrToken` |
| `card-templates.json` | шаблоны: две стороны, размер, слои, шрифты, версии |
| `points.json` | журнал баллов (есть) |
| `school-courses.json` | курсы → модули → уроки → материалы/задания/тесты |
| `school-progress.json` | прохождение: уроки, позиция видео, тесты |
| `school-work.json` | сданные задания, оценки, комментарии, повторные отправки |
| `documents.json` | документы проекта: тип, номер, реквизиты, версии, статус |
| `doc-templates.json` | шаблоны документов с переменными |
| `activity.json`, `person-notes.json`, `backup/` | есть |

### Интерфейс

* `/admin` становится оболочкой с **боковым меню** (на десктопе) и шторкой
  (на телефоне). Разделы: Обзор · Участники · Редакции · Материалы · Пресс-карты ·
  Медиашкола · Документы · Поддержка · Почта · Сайт · Сервер.
* Карточка участника — отдельный экран `#person/ID` с 9 вкладками.
* Конструктор карт — `#cards/editor/ID`, холст с перетаскиванием слоёв.
* `/school` — кабинет ученика; `#teach` — кабинет преподавателя; конструктор курсов
  внутри админки.
* `/verify` — публичная страница проверки карты и сертификата по коду.
* Стиль: та же палитра и типографика, оранжевый — только акценты и кнопки.

### PDF с кириллицей

Своего PDF-движка в PHP нет, composer и сторонние библиотеки на хостинге не нужны:
минимальный генератор `api/lib/pdf.php` уже собран для пресс-карты: встроенный
Golos Text (`tools/build-card-fonts.py`, `.woff2` → `.ttf` + метрики), текст остаётся
текстом, печать корректная. DOCX для этапа 7 собирается как ZIP с XML, если на
хостинге есть `ZipArchive`, иначе — через запасной путь без сжатия.

## 4. Порядок работ

| Этап | Что делаем | Критерий готовности |
|---|---|---|
| **0–1. Фундамент** (сделано) | права, баллы, копии, расширенная карточка и список участников | 45 проверок API |
| **2. Оболочка админки** | боковое меню, разделы, глобальный поиск, уведомления, «требует внимания», графики на реальных данных | из админки открываются все разделы, обзор считает реальные цифры |
| **3. Участники** | таблица с фильтрами и сортировкой, экран участника `#person/ID` с 9 вкладками, быстрые действия, история изменений | можно открыть любого участника, отредактировать, начислить баллы, приостановить |
| **4. Карты: управление** (сделано: жизненный цикл ранее; теперь PDF, `/verify`, доставка) | жизненный цикл, продление, отзыв, история, центр заявок, страница `/verify`, PDF с данными | карта выпускается, скачивается в PDF, проверяется по номеру и коду |
| **5. Конструктор карт** | шаблон из двух изображений, слои, переменные, две стороны, предпросмотр на реальном человеке, проверки переполнения | свой шаблон → выпуск карты по нему без правки кода |
| **6. Медиашкола** | курсы/модули/уроки, плеер с прогрессом, задания, проверка, тесты, кабинеты ученика и преподавателя, сертификаты с проверкой | курс создаётся в админке, ученик проходит, преподаватель проверяет |
| **7. Документы** | шаблоны (приказ, заявление, согласие и др.), редактор с переменными, версии, нумерация, PDF/DOCX, журнал | документ создаётся и выгружается в PDF и DOCX |
| **8. Юридический чек-лист** | документы, техмеры, оргмеры, запросы субъектов, хранение, удаление, копии, доступ, инциденты | чек-лист заполнен; почта внесена, уведомление РКН подано — остаток владельца: дождаться ответа |

Каждый этап — отдельный pull request, отдельная проверка, без разрушительных миграций.

## 5. Что нужно согласовать до этапа 6

1. **Видеоуроки.** Хостинг общий (Sprinthost), бюджет ≤150 ₽. Варианты:
   (а) встраиваем плееры VK Видео / Rutube — бесплатно, без нагрузки на сервер,
   прогресс считаем по времени просмотра; (б) загружаем короткие ролики на сервер —
   работает без внешних сервисов, но 10–15 уроков съедят место и трафик.
   Рекомендация: (а) для длинных уроков, (б) только для коротких нарезок.
2. **Операторы персональных данных.** Оба основателя указаны в документах с ИНН;
   юридическая ответственность за формулировки документов принята на себя в рамках
   аудита. Внешнее юридическое ревью не требуется по решению владельца.
3. **Согласие на распространение** (ст. 10.1 152-ФЗ) — сделано отдельным документом;
   публикация закрыта, пока не приняты оба согласия.
