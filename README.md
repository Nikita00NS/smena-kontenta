# Смена контента — сайт проекта

Молодёжное медиа, медиашкола и сообщество авторов из регионов.
Главная особенность — интерактивная карта России: выбираешь регион и видишь материалы оттуда.

Сайт **статический**: обычные HTML-файлы, без серверов и подписок. Открывается двойным щелчком
по `index.html` и бесплатно публикуется на GitHub Pages.

---

## 1. Что уже работает

**Медиа**
- Главная в формате редакционной страницы: главный материал, лента, бегущая строка, рубрики,
  форматы, «лица проекта», возможности, три шага до первой публикации.
- Лента материалов с фильтрами: тема, формат, федеральный округ, регион, поиск, сортировка.
- Страница материала: обложка, автор, лид, буквица, цитаты, подзаголовки, теги, полоса
  прогресса чтения, похожие материалы.
- Поиск по всему сайту (иконка в шапке или клавиша `/`).

**Карта регионов**
- 84 субъекта РФ: поиск, фильтр по федеральным округам, масштаб, перетаскивание,
  переключение на список, работа с клавиатуры.
- Легенда «есть материалы / публикаций пока нет», подсказки при наведении.
- Страница региона: материалы оттуда, мини-карта, честное сообщение, если публикаций нет.

**Аккаунты и публикация**
- Регистрация и вход: имя, почта, пароль, регион, роль, согласие с документами.
- Личный кабинет: прогресс, публикации и черновики, настройки профиля, пресс-карта.
- Редактор материала: заголовок, лид, текст, тема, формат, регион, обложка (файл или ссылка),
  черновик и публикация.
- Опубликованный материал сразу попадает в ленту, на главную и на страницу своего региона,
  с подписью автора.

**Пресс-карта**
- Пресс-карта автора выдаётся **после 5 опубликованных материалов** (число меняется
  в панели проекта). До этого в кабинете виден прогресс: сколько осталось и что карта даёт.
- В карте: номер (`СК-2026-101`), имя, роль, регион, дата выдачи, срок действия, кем выдана.
- Карту можно распечатать — на печати остаётся только карточка.

**Панель проекта** (`admin.html`)
- Данные организации и центра: название, руководитель, почта, телефон, город — они печатаются
  на пресс-карте и в документах.
- Правила пресс-карты: серия, год, число публикаций до выдачи, срок действия.
- Список авторов с числом публикаций и статусом карты, выгрузка всех данных в JSON.
- Доступ: первый зарегистрированный аккаунт или роль «Редактор».

**Документы** (`docs.html`) — шесть PDF в `assets/docs/`:
пресс-кит, редакционная политика, памятка автору, программа медиашколы,
политика конфиденциальности, пользовательское соглашение.
Пересобираются одной командой (см. раздел 3).

**Оформление**
- Чёрная тема: почти чёрный фон, светлый текст, оранжевый акцент. Все цвета — в блоке токенов
  в начале `site.css` (раздел 02) и переопределены один раз в разделе 18.
- Логотип: `assets/img/logo.png` (белый), `logo-dark.png` (для PDF), `logo-mark.png`,
  фавиконки 32/128/180 px.
- Анимации: появление блоков при прокрутке, счётчики цифр, параллакс главного фото,
  бегущая строка. Отключаются при `prefers-reduced-motion`.

## 2. Как посмотреть сайт

**Способ 1.** Открыть `index.html` двойным щелчком — работает прямо с диска.

**Способ 2.** Как на настоящем сервере:

```bash
python3 -m http.server 8000
```

и открыть `http://localhost:8000`.

## 3. Как менять содержание

Почти весь текст — в файле **`assets/js/data.js`** (внутри комментарии):

| Что менять | Где |
|---|---|
| Почта, название, город, год | блок `brand` (почта также в панели проекта) |
| Документы на странице «Документы» | массив `docs` |
| Авторы и подписи | массив `authors` |
| Материалы редакции | массив `articles` |
| Рубрики и форматы | `topics`, `formats` |

Фотографии — в `assets/img/`, миниатюры для карточек — в `assets/img/thumb/`.
Страницы `about.html`, `media-school.html`, `partners.html` — обычный HTML, текст правится в них.

### Документы (PDF)

```bash
pip install reportlab
python3 tools/build-docs.py
```

Скрипт пересобирает все шесть PDF из текста внутри `tools/build-docs.py`.
Меняете формулировки — пересобираете — файлы на сайте обновляются.

### Логотип

```bash
python3 tools/make-logo.py путь/к/новому-логотипу.png
```

Скрипт сделает белый логотип для сайта, чёрный для документов, знак и все фавиконки.

## 4. Как работает регистрация (важно понимать)

Сейчас аккаунты, черновики и публикации хранятся **в браузере** (`localStorage`).
Это значит:

- регистрация, публикация и пресс-карта работают по-настоящему;
- но материалы видны только на том устройстве, где их создали;
- пароль хранится в виде необратимого хеша, однако это **не** серверная система входа.

Что делать, когда понадобится, чтобы авторы видели работы друг друга:

1. Зарегистрировать бесплатный проект в Supabase (или Firebase) — это база данных с входом.
2. В `assets/js/store.js` заменить чтение/запись `localStorage` на запросы к Supabase.
   Весь остальной сайт менять не нужно: он общается с данными только через этот файл.
3. Пароли, подтверждение почты и права доступа берёт на себя сервис.

Файл `store.js` специально написан отдельно: это единственное место, которое придётся
переписать при переходе на настоящий сервер.

## 5. Как опубликовать сайт бесплатно

### GitHub Pages

1. Создать репозиторий на GitHub.
2. Загрузить все файлы проекта.
3. **Settings → Pages → Source: Deploy from a branch → Branch: main, папка / (root) → Save.**
4. Через минуту сайт доступен по адресу `https://ваш-логин.github.io/имя-репозитория/`.

Файл `.nojekyll` уже лежит в проекте — он нужен, чтобы GitHub не ломал папки и шрифты.

### Cloudflare Pages

**Workers & Pages → Create → Pages → Upload assets**, перетащить папку проекта.
Настройки сборки оставить пустыми.

## 7. Документы и закон

Сайт собирает имя, почту и регион — значит, по 152-ФЗ нужны политика конфиденциальности
и согласие пользователя. Это сделано:

- согласие с документами — обязательная галочка при регистрации;
- политика конфиденциальности и пользовательское соглашение — отдельные PDF;
- ссылки на них — в подвале каждой страницы и на странице «Документы»;
- политика честно описывает, что данные пока хранятся в браузере пользователя.

Оператором может быть и физическое лицо: регистрация ИП или ООО не требуется,
но ФИО и ИНН учредителей должны быть указаны в документах. Они заполняются
в панели проекта (раздел «Учредители») и в `tools/build-docs.py` — блок `PROJECT`.
Пока данные не заполнены, в таблице стоит прочерк с пояснением.

Что стоит сделать до публичного запуска:

- вписать рабочую почту (сейчас её нет — на сайте честно написано «появится к запуску»);
- указать ФИО и ИНН учредителей и пересобрать PDF;
- показать политику и соглашение юристу — это шаблоны, а не заключение специалиста;
- если появится серверное хранение, обновить политику **до** его запуска.

## 8. Лицензии и источники

- Логотип — собственная айдентика проекта (`assets/img/logo*.png`).
- Шрифты: Unbounded, Golos Text, JetBrains Mono — SIL Open Font License 1.1.
- Границы регионов: набор `imsha/russia_geojson_regions_2021` (см. `tools/README.md`).
- Изображения сгенерированы для прототипа: чужих прав не нарушают, но перед публичным
  запуском их нужно заменить на снимки авторов.
- Тексты в ленте — образцы оформления, а не описание реальных событий.
