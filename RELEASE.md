## 2. Статус решений и owner-задач

1. **Почта.** Адреса внесены в код, подвал, страницу поддержки, партнёров и PDF.
   Пароли ящиков, SMTP/IMAP и проверка отправки — в панели проекта («Почта»).
2. **РКН.** Уведомление подано основателем, ожидается ответ / внесение в реестр
   (до 30 рабочих дней). Рабочие материалы сохранены в `tools/rkn-uvedomlenie.md`
   и `tools/rkn-forma-zapolneniya.md`. Повторно подавать не нужно, если данные не менялись.
3. **Ответственные редакторы.** Назначить в админке, кто проверяет материалы,
   согласия и выдаёт карты. Это операционная задача, не блокер кода.
4. **Выкладка.** Разрешение получено. Деплой автоматический; статус — во вкладке Actions.

Регион первого запуска — **Москва** (`assets/js/data.js` → `brand.launchRegion`).

## 4. Порядок выкладки и проверки

1. Прогнать проверки локально (наборы ниже) → pull request в `main` → merge → GitHub Actions отправляет файлы по FTP. Статус — во вкладке Actions.
2. После деплоя открыть главную, `/verify`, `/docs`, `/support`, `/partners`;
   проверить почту в подвале и ссылку поддержки.
3. В кабинете скачать PDF действующей карты и распечатать в масштабе 100 %:
   стороны должны быть 85,6 × 54 мм. Проверить карту через `/verify`.
4. В админке проверить ящики (IMAP/SMTP), выдать доступы редакторам, назначить ответственных.
5. Наполнить ленту реальными материалами авторов и проверить права на фотографии.
6. Убедиться, что HTTPS включён в панели Sprinthost (Let's Encrypt) и работает перенаправление.
7. Дымовую проверку продакшена можно запустить из среды с доступом к домену:
   `python3 tools/production-smoke.py --base https://smenakontenta.ru --stamp 2026-11-12-04`.

Проверки в CI и локально:

```bash
node --check assets/js/app.js && node --check assets/js/store.js
node tools/tests/php-syntax.js
node tools/tests/i18n-check.js
node tools/tests/pages-smoke.js
node tools/tests/profile-consent.js
node tools/tests/verify-page.js
node tools/tests/card-document.js
node tools/tests/team-flows.js
node tools/tests/api-checks.js
python3 tools/tests/docs-check.py
```

команда/вход — 19; остальные наборы без ошибок.

## 6. Чего в проекте нет — и это осознанно

- Нет выдуманных новостей, «команды» и чужих логотипов.
- Нет платных сервисов, подписок и карт с платной лицензией.
- Нет сбора данных, которые не нужны для работы сайта.
- Материалы авторов публикуются на сайте; в площадках проекта — только анонсы
  конкурсов и новости команды, работы участников — лишь с отдельной отметки в согласии.

## 7. Серверная приёмная (актуально)

Аккаунты, согласия, баллы, портфолио, пресс-карты и отправленные материалы живут
на сервере: `api/index.php` и JSON-файлы в `smena-data/` вне `public_html`.
В браузере остаются токен сессии, копия профиля для отрисовки и черновики,
пока автор не отправил их на проверку.

- Регистрация без настроенного SMTP невозможна (API отвечает 503): «мёртвые»
  адреса не создаются. Код подтверждения — 6 цифр, 30 минут, повтор не чаще 45 секунд.
- Чувствительные действия в панели подтверждаются кодом на почту вошедшего
  администратора; подтверждение действует 30 минут. Служебная диагностика закрыта
  ролью/паролем редакции.
- При первой установке, если `smena-data/config.json` ещё нет, создаётся случайный
  пароль и один раз пишется в `smena-data/BOOTSTRAP-PAROL.txt` (вне веба).
  После смены пароля файл удаляется, на сервере остаётся только хеш.
- Журнал действий редакции — `smena-data/admin-log.json`, виден во вкладке «Сервер».
- Резервные копии: ежедневно в `smena-data/backup/ГГГГ-ММ-ДД`, хранение 14 дней,
  проверка SHA-256 каждого файла; личные документы (`private/`) входят в копию,
  публичные загрузки (`uploads/`) — нет. Старые копии удаляются только после успешной новой.
- Данные и копии закрыты от веба `.htaccess`; служебные файлы `api/lib/` также закрыты.
